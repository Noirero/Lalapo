============================================================
3. PR POLICY
============================================================

Satu logical change biasanya tetap satu logical PR sampai terintegrasi.

Default:
- satu task/logical change -> satu work branch -> satu PR main.

Update PR yang sama jika:
- corrective fix masih bagian logical change;
- CI failure memperlihatkan defect dari change yang sama;
- review menemukan regression dalam scope yang sama.

Buat PR terpisah bila:
- perubahan independen secara produk/engineering;
- membutuhkan urutan merge berbeda;
- risk/validation class materially berbeda;
- rollback independen bernilai;
- PR original sudah merge;
- review lebih aman bila dipisah.

CI retry/reconstruction mechanics bukan alasan otomatis membuat PR baru.

============================================================

Test/build/CI/runtime evidence hanya berlaku untuk code/SHA yang benar-benar diuji.

Jangan:

Sebelum merge/release:

- cocokkan dengan workflow run/evidence;
- jika code material berubah setelah validation, tentukan validation yang perlu diulang berdasarkan risiko.

Prinsip:
VALIDATION PROVES THE CODE THAT RAN, NOT CODE THAT CHANGED AFTERWARD.

============================================================
7. VALIDATION CLASSIFICATION
============================================================

A source/static, B local unit/integration, C CI, D emulator/runtime,
E physical device, F release artifact, G production evidence.
Levels are distinct; no automatic transfer of proof.
Actual CI Checks: format/JVM/legacy migration fixture/SQLDelight,
plus Android 15 connectedDebugAndroidTest if job really executes and passes.
Actual test count/selection must be verified from XML/log if claimed.
CI green is NOT physical-device QA, real player/mpv, Cast/PiP, external
provider/OAuth/Google Drive validation, or signed release artifact proof.
Distinguish FAILED, CANCELLED, SKIPPED, NOT TRIGGERED, SUCCESS.

============================================================
9A. TARGETED-FIRST CI FAILURE RECOVERY
============================================================

1. Capture exact repo/base/head SHA, failing run/attempt, workflow/job/step,
   first relevant error/log, XML/artifacts, emulator/test selection.
2. Classify: application regression, pre-existing baseline, infrastructure,
   test harness, external dependency, or UNKNOWN. Separate PROVEN/INFERENCE/
   HYPOTHESIS; matching signatures alone do not prove flakiness.
3. Choose highest-information-gain targeted diagnostic (formatter/compile,
   focused JVM or instrumentation test, logcat, known-good diff, small A/B).
   Never rerun full emulator merely for detectable formatting/static errors.
4. Fix owning layer using smallest correct change, without weakening test,
   assertion, fixture, golden, migration, or acceptance guard.
5. Run targeted regression; update hypothesis from result.
6. Return to every MANDATORY exact-head validation before readiness.
   Targeted PASS never replaces required final full CI/Android proof.
Full rerun as first experiment is justified only when combined-suite behavior,
proven transient infrastructure or mandatory gate makes it necessary.
No blind retries, bypass, policy/label changes, or synthetic proof.

============================================================
29. MULTI-PR / DEPENDENCY
============================================================

Conditional validated combined-state preservation applies only if PRs
depend on each other, share regression surface/stale baseline, require
corrective integration fix, or reproduce a previously validated candidate.
For those cases map prerequisites, follow-up fixes, exact validated SHA,
logical integration order; reconcile stale changes against current target
and preserve material behavior/known fixes via targeted diff/history/semantic
checks. Green individual PRs do not prove combined state.
Do not impose full-tree equivalence/heavy retests on independent PRs.
Additional CI/emulator is required only by existing policy or actual risk.
No new routing or merge authorization is created.
